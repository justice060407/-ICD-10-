## 一、为什么开这门课（立项论证要点）

### 1.1 产业需求侧的真实缺口

医疗 AI 企业招人时，**最缺的不是会调 API 的人，而是懂"病历数据怎么变成可用资产"的人**。
行业普遍存在三重断层：

| 断层 | 表现 | 本课程对应环节 |
|---|---|---|
| 数据侧断层 | 算法工程师不敢碰病历，医学信息专业不懂算法 | 合成病历 → 脱敏 → NER |
| 编码侧断层 | 病案编码靠人工，DRG/DIP 支付改革后需求暴涨 | ICD 编码与评测 |
| 落地侧断层 | 通用大模型在临床场景答非所问、不敢上线 | LoRA 领域适配 + 安全兜底 |

### 1.2 政策驱动

- DRG/DIP 支付方式改革全面落地，病案首页编码质量直接关系医院收入
- 电子病历系统应用水平分级评价推动病历结构化
- 《生成式人工智能服务管理暂行办法》要求从业人员具备合规意识

### 1.3 与现有课程的差异（创新性）

| 现有课程 | 局限 | 本课程的补位 |
|---|---|---|
| 自然语言处理 | 以通用语料（新闻、wiki）为主 | 全程使用临床文本，直面术语与隐私难题 |
| 数据挖掘 | 通用算法，无行业约束 | 嵌入 ICD/DRG 业务规则与合规约束 |
| 医学信息学 | 偏系统运维与标准 | 偏算法实现与模型落地 |
| 大模型应用开发 | 偏调用与提示工程 | 覆盖数据治理→微调→评测全链路 |

## 二、课程目标（可考核）

完成本课程后，学生应能够：

1. **CO1** 独立编写符合国标的病历脱敏管道，输出可审计的替换日志
2. **CO2** 使用词典/规则与序列标注两种方式完成临床实体抽取，并对比优劣
3. **CO3** 将自由文本病历结构化为规范 JSON，字段完整率 ≥ 90%
4. **CO4** 实现并评测 ICD-10 编码映射，理解编码错误对 DRG 支付的影响
5. **CO5** 用小模型 + LoRA 完成临床领域适配，说明微调与提示工程的取舍
6. **CO6** 构建含安全兜底的患者问答原型，并完成四维人工评测
7. **CO7** 说出至少 6 部相关法规的约束点，在作业中主动落实合规要求

## 五、实验项目详表

### 实验 1 · 合成病历构造与脱敏管道（6 学时）
- **任务**：编写 20 条虚构病历（覆盖 8 个以上 ICD 章节）；实现 18 类隐私字段识别与一致性代理替换
- **交付**：`data/synthetic_records_20.jsonl`、`src/deid_pipeline.py`、审计日志
- **评分点**：字段覆盖率、一致性（同一人全篇同一假名）、残留扫描通过、审计可追溯

### 实验 2 · 临床实体识别（4 学时）
- **任务**：先用词典最大匹配建立基线，再用标注集训练序列标注模型
- **交付**：BIO 标注集、F1 对比表
- **评分点**：词典基线与模型的差距分析是否到位（**不要求模型一定更强**）

### 实验 3 · 病历结构化（2 学时）
- **任务**：设计 Schema，把自由文本转为可入库 JSON
- **交付**：`schema.json` + 20 条结构化结果
- **评分点**：字段完整率、类型合规性、异常值处理

### 实验 4 · ICD-10 编码与错误归因（4 学时）
- **任务**：实现精确 / 同义 / 模糊三级匹配，评测 Top-1、Top-3
- **交付**：编码对照表、错误归因报告
- **评分点**：是否理解"编码错误 = 医保支付错误"

### 实验 5 · LoRA 领域适配（4 学时）
- **任务**：构建三类指令数据；A/B 档完成训练，C 档做少样本对比
- **交付**：权重（或对比报告）
- **评分点**：格式稳定性、任务完成度、显存/时间记录

### 实验 6 · 患者问答与安全兜底（4 学时）
- **任务**：检索增强问答原型 + 四维人工评测
- **交付**：Demo + 评测报告
- **评分点**：**有无越界诊断**（一票否决项）

### 实验 7 · 工程化交付（2 学时）
- **任务**：把个人成果打包为可复现镜像
- **交付**：Dockerfile + 一键复现脚本

## 七、算力分级教学方案（民办本科的现实解法）

| 档位 | 条件 | 实验 5 做法 | 教学目标不打折的关键 |
|---|---|---|---|
| A 档 | 24GB 显卡 ×1 | Qwen2.5-1.5B + bf16 + LoRA r=16 | 完整体验训练 |
| B 档 | 8GB 显卡 | Qwen2.5-0.5B + 4bit + LoRA r=8 | 体验显存约束下的工程取舍 |
| C 档 | 纯 CPU | 不训练，做 3-shot 提示基线对比 | **把"训练不了"本身变成教学内容** |

> C 档不是降低要求，而是让学生理解：工业界大量场景也受算力约束，
> "什么时候不该微调"是比"怎么微调"更值钱的判断力。

## 九、微课 Docker 化方案

```
clinical-llm-course:base     # 实验 1-4、6-7，离线可跑，无显卡要求
clinical-llm-course:lora     # 实验 5，按需构建（--target lora）
```

- 一键起环境：`docker compose up course`
- 边讲边演示：`docker compose up jupyter`（http://localhost:8888）
- 有显卡：`docker compose --profile gpu up trainer`
- 微课切片：每个实验录 8–12 分钟视频，配套 `labs/` 下的实验指导书

## 十、开课前的三项准备（给任课教师）

1. **自己先跑一遍**：`docker compose up course`，看产出目录是否齐全
2. **把合规清单过一遍**：尤其是第五条操作禁令，第一堂课就要讲
3. **联系 1–2 家本地医疗 AI 企业**：请他们看大纲并给出用人反馈，
   这份反馈是立项答辩时最有说服力的材料
