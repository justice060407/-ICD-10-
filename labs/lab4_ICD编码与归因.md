**学时**：4 学时 | **性质**：核心实验 | **对应岗位**：病案编码 / DRG 专员
**对应课程目标**：CO4 | **交付**：编码对照表 + 错误归因报告

## 一、你要做什么

把自由文本的诊断名称，映射到标准的 ICD-10 编码。

### 先理解一件事：为什么这个岗位突然值钱了

DRG/DIP 支付方式改革之后，医保**不再按项目付费，而是按病组打包付费**。
同一个病人，编成不同的码，医院拿到的钱可能差好几倍。

所以编码错误不再只是"档案管理不规范"，而是**直接影响医院收入的财务问题**。
这就是为什么病案编码员这两年薪资涨得快，也是为什么家企业愿意为这个岗位付钱。

你在这个实验里每调整一个匹配阈值，本质上是在模拟一次"编码质量控制"。

---

## 二、三级匹配策略

管道用的是逐级降级：

```
L1 精确匹配   输入的归一化诊断名 == 字典的键
      ↓ 未命中
L2 包含匹配   字典术语是输入的子串（如"复发性抑郁障碍" ⊂ "复发性抑郁障碍中度发作"）
      ↓ 未命中
L3 模糊匹配   编辑距离相似度 ≥ cutoff（默认 0.72）
```

**归一化**是关键前置步骤，它包括：

- 截取**第一诊断**（主要诊断优先 —— 按 `，,；;` 切，取第一段）
- 去噪字符
- 同义词映射（ synonyms 表）

### 步骤 2：看懂为什么有 3 条是 L2 而不是 L1

打开 `out_lab4/icd_predict.jsonl`，找出 `命中层级 == "L2-包含"` 的那几条，
看它们的 `原始诊断`、`归一化`、`gold`、`top1` 四个字段。

你会发现一个规律：**这些诊断都带了修饰成分**（如"伴多个并发症"、"中度发作"）。

这对应病案管理的真实规则：**主要诊断选择要考虑合并症的编码粒度**。
同一疾病，有没有合并症，编的码是不一样的。

### 步骤 3：制造失败（重要）

现在的准确率是 100%，这**不利于学习**。老师要看的是你处理失败的能力。

用三种方式人为制造困难，看你把它打到多低：

```powershell

python src\icd_map.py --in out\records_deid.jsonl --out out_lab4 --cutoff 0.3

# 实验 B：把阈值拉到很高，看召回率怎么崩
python src\icd_map.py --in out\records_deid.jsonl --out out_lab4 --cutoff 0.95

# 实验 C：自己造 5 条刁钻诊断（口语化 / 错别字 / 多诊断混合），加进去跑
```

把三个结果记进一张表：

| cutoff | Top-1 | Top-3 | L1 | L2 | L3 | 你的观察 |
|---|---|---|---|---|---|---|
| 0.30 | | | | | | |
| 0.72 | 1.0 | 1.0 | 17 | 3 | 0 | 基线 |
| 0.95 | | | | | | |

**这张表就是你这个实验最有价值的产出。** 它能说明你对阈值调参的理解，
比跑出一个 100% 有意义得多。

### 步骤 4：错误归因

从实验 C 的失败案例里挑 3 个，按这个模板写归因：

```
【案例】
  原始诊断：...
  归一化后：...
  金标准码：...
  系统预测：...

【归因】直接原因是什么？
  （归一化把逗号删了？术语表没覆盖？还是相似度算错？）

【业务影响】如果这条真的错编了，DRG 分组会怎么变？
  （举个具体的钱的例子，哪怕是粗略估计）

【修正方案】你怎么改让它对？改完之后会不会引入新问题？
```

### 步骤 5：理解阈值为什么是 0.72

这个数字不是拍脑袋的。改一改 `cutoff`，画出"阈值 → Top-1 准确率"的变化，
体会一下：

- 阈值低 → 什么都敢匹配 → **假编码**（把 A 病编成 B 病，这是最坏的错误）
- 阈值高 → 稍有不同就放弃 → 落到人工编码，**效率下降但不犯错**

医疗场景该往哪边偏？**往保守那边。** 原因写在思考题里。

## 五、常见坑

| 坑 | 说明 |
|---|---|
| 归一化时**删掉逗号** | `"社区获得性肺炎，未指明病原体"` 会粘成一大串，相似度被稀释到阈值以下。正确做法是**取第一诊断** |
| 术语长度阈值挡掉短词 | 曾经因为要求"术语 ≥4 字"，把"肝硬化"这类三字术语全漏了 |
| 只优化 Top-1 不看别的 | 真实场景里 Top-3 更重要——编码员是从 Top-3 里挑的，系统给对候选就行 |
| 把 gold 当成"标准答案"去拟合 | 那叫作弊。真实项目里没有 gold，只有编码员的复核 |
| 觉得"100% 准确率"很牛 | 20 条自造数据上的 100% 毫无意义。**说出来才算懂** |

## 六、项目踩过的真坑（可以直接当案例）

开发这套代码时，Top-1 从 0.8 升到 1.0 的过程就是被这两条卡住的：

1. **归一化删逗号导致长串稀释相似度** → 改为取第一诊断
2. **术语长度阈值把"肝硬化"挡在门外** → 把阈值从 4 字降到 3 字，
   同时补充"复发性抑郁障碍中度发作"这类带修饰语的细粒度条目

第二个问题特别典型：**你以为是数据不全，其实是规则卡错了。**
